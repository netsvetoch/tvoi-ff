# TVOI FF

React 19 SPA built with TypeScript, Vite, Gravity UI, TanStack Query, and TanStack Table.

## Setup

- Use Node.js `26.8.1` (`.nvmrc`) and pnpm `12.0.0` (`packageManager` in `package.json`).
- Install dependencies with `pnpm install --frozen-lockfile`.
- `package.json` is the tooling source of truth. The root README still mentions Bun and Biome; do not use those commands for this application.

## Commands

- Development server: `pnpm dev`.
- Production build, including type checking: `pnpm build`.
- Full static validation: `pnpm lint:all`.
- Type checking: `pnpm typecheck`.
- ESLint: `pnpm lint`; targeted lint: `pnpm exec eslint src/path/to/file.ts --quiet`.
- Format changed files with `pnpm exec prettier --write <files>`; check them with `pnpm exec prettier --check <files>`.

## Project Map

- `src/app/`: application bootstrap, providers, layout, and routing.
- `src/pages/`: route-level features; `src/widgets/`: reusable feature compositions.
- `src/shared/`: shared UI, hooks, helpers, and generated API clients.
- `openspec/specs/`: current behavior specifications; `openspec/changes/archive/`: completed change history.
- `repos/`: reference checkouts of upstream Gravity UI projects. They are not pnpm workspaces or application source; change them only when the task explicitly targets one of those repositories.

## Implementation Rules

- Use the `@/*` alias for cross-layer imports from `src`; keep relative imports for nearby files within one module.
- Build application UI from installed `@gravity-ui/*` packages and existing shared components. Never import application code from `repos/*`.
- Tables use headless `@tanstack/react-table` v9 and the shared `src/shared/ui/GTable.tsx`; do not reintroduce `@gravity-ui/table`. See `openspec/specs/table-ui/spec.md`.
- Files under `src/shared/api/` marked as generated by `@hey-api/openapi-ts` are generated output. Do not hand-edit them; locate or restore the generator configuration when an API change is required.
- React Compiler is enabled in `vite.config.ts`. Do not add `useMemo` or `useCallback` by default; add manual memoization only for a measured need or an API that requires stable identity.

## Gotchas

- TypeScript, ESLint, and Vite exclude `repos/`; validate a referenced repository with its own manifest and instructions instead of root commands.

## Skill Loading

Before editing files for a substantial task:

- Run `pnpm dlx @tanstack/intent@latest list` from the workspace root to see available local skills.
- If a listed skill matches the task, run `pnpm dlx @tanstack/intent@latest load <package>#<skill>` before changing files.
- Use the loaded `SKILL.md` guidance while making the change.
- Monorepos: when working across packages, run the skill check from the workspace root and prefer the local skill for the package being changed.
- Multiple matches: prefer the most specific local skill for the package or concern you are changing; load additional skills only when the task spans multiple packages or concerns.

## Spec-driven workflow (OpenSpec)

- Non-trivial changes (new endpoint, DB schema change, new integration, multi-file feature): start with an OpenSpec proposal. Create `openspec/changes/<change-name>/` with `proposal.md`, `tasks.md`, and spec deltas, then confirm it with the user before implementing.
- Trivial changes (bugfix, typo, small refactor): implement directly, no proposal.
- Existing specs live in `openspec/specs/`; read them before proposing changes that touch the same domain. Archived changes are in `openspec/changes/archive/`.
- While implementing an approved change, check off tasks in its `tasks.md`; when done and verified, move the change to `openspec/changes/archive/` and merge its deltas into `openspec/specs/`.
