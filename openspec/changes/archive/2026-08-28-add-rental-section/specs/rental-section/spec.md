## Purpose

Обеспечивает раздел «Прокат»: каталог типов предметов с бронированием и страницу личных аренд и страйков пользователя через rental API (`https://api.test.profcomff.com/rental`) с использованием общего токена авторизации приложения.

## ADDED Requirements

### Requirement: Секция «Прокат» в навигации

Приложение SHALL отображать пункт «Прокат» в боковой навигации (меню десктопа и мобильное меню); клик по пункту SHALL открывать каталог, а пункт SHALL подсвечиваться как текущий, пока открыт любой маршрут раздела.

#### Scenario: Переход из навигации

- **WHEN** пользователь кликает по пункту «Прокат»
- **THEN** приложение открывает страницу каталога `/rental`

#### Scenario: Подсветка активного раздела

- **WHEN** открыт маршрут `/rental` или `/rental/my`
- **THEN** пункт «Прокат» отмечен как текущий в навигации

### Requirement: Каталог типов предметов

Страница каталога SHALL показывать типы предметов карточками с изображением, названием, описанием, количеством доступных предметов и признаком недоступности (включая cooldown с датой окончания) и не SHALL требовать входа для просмотра. Для каждого типа, у которого `availability` истинна, есть доступные предметы и не действует cooldown, карточка SHALL предоставлять действие бронирования.

#### Scenario: Просмотр каталога без входа

- **WHEN** неавторизованный пользователь открывает каталог
- **THEN** приложение запрашивает список типов и показывает карточки без требования входа

#### Scenario: Бронирование без входа

- **WHEN** неавторизованный пользователь нажимает «Забронировать»
- **THEN** приложение перенаправляет его на страницу входа

#### Scenario: Бронирование авторизованным пользователем

- **WHEN** авторизованный пользователь бронирует доступный тип
- **THEN** приложение создаёт сессию аренды с токеном пользователя, показывает уведомление об успехе и обновляет каталог

#### Scenario: Недоступный тип

- **WHEN** тип недоступен, не имеет доступных предметов или в cooldown
- **THEN** действие бронирования для него отключено

#### Scenario: Ошибка бронирования

- **WHEN** сервер отклоняет бронирование (нет прав, нет предметов, сессия уже существует)
- **THEN** приложение показывает текстовое сообщение об ошибке из ответа

### Requirement: Личные аренды пользователя

Страница `/rental/my` SHALL требовать входа и показывать сессии пользователя (`/rental-sessions/user/me`) с фильтром по статусам (зарезервирована, активна, отменена, просрочена, возвращена, отклонена, истекла), названием типа предмета и временными метками; зарезервированные сессии SHALL можно отменить с подтверждением; просмотр сессии SHALL открывать детали через `/rental-sessions/{session_id}`. Страница SHALL также показывать страйки пользователя (`/strike/user/{user_id}`).

#### Scenario: Список своих сессий

- **WHEN** авторизованный пользователь открывает `/rental/my`
- **THEN** приложение загружает его сессии и страйки с его токеном

#### Scenario: Фильтрация по статусу

- **WHEN** пользователь выбирает статусы в фильтре
- **THEN** приложение запрашивает сессии с соответствующими флагами `is_*`

#### Scenario: Отмена брони

- **WHEN** пользователь подтверждает отмену зарезервированной сессии
- **THEN** приложение вызывает отмену, обновляет список и показывает уведомление

#### Scenario: Нет страйков

- **WHEN** у пользователя нет страйков
- **THEN** приложение показывает сообщение «Страйков нет»

#### Scenario: Доступ без входа

- **WHEN** неавторизованный пользователь открывает `/rental/my`
- **THEN** приложение перенаправляет его на страницу входа

### Requirement: Авторизация запросов проката

Все запросы раздела, требующие авторизации, SHALL передавать сохранённый токен сессии через опцию `auth` сгенерированного клиента; поток входа приложения изменяться для этого не SHALL.

#### Scenario: Запрос с токеном

- **WHEN** раздел выполняет авторизованный запрос
- **THEN** запрос несёт токен из сохранённых данных входа в заголовке `Authorization`

#### Scenario: Отказ сервера

- **WHEN** сервер отвечает ошибкой авторизации или нехватки прав
- **THEN** приложение показывает сообщение об ошибке из ответа и не теряет данные других разделов
