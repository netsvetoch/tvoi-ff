## Why

API-клиент сервисов (`src/shared/api/services/`) полностью сгенерирован, но не используется: в приложении нет раздела «Сервисы». Бэкенд хранит категории с кнопками-ссылками; у каждой кнопки есть тип открытия ссылки (`inapp` — маршрут приложения, `internal` — встроенный браузер/iframe, `external` — внешний браузер), иконка и доступность для текущего пользователя (`view`: `active`/`blocked`/`hidden`, вычисляется по scopes). Нужен UI, который показывает каталог сервисов и корректно открывает каждую кнопку по её типу.

## What Changes

- Добавить в навигацию (пункт `AsideHeader` на десктопе и бургер-меню на мобильных) новый пункт «Сервисы», ведущий на `/services`.
- Добавить страницу каталога `/services`: категории (в порядке `order`) с кнопками; запрос `GET /category?info=buttons` с токеном авторизации через опцию `auth`, чтобы поле `view` отражало скоупы пользователя.
- Правила отображения кнопок:
  - `view: active` — кликабельна;
  - `view: blocked` — видна, но неактивна (не хватает scopes);
  - `view: hidden` — не отображается вовсе.
- Открытие кнопки по типу `type`:
  - `inapp` — внутренняя навигация приложения по ссылке-маршруту через роутер;
  - `internal` — открытие страницы-просмотра `/services/$buttonId`, где ссылка рендерится в iframe на всю доступную область (встроенный «браузер»);
  - `external` — открытие ссылки в новой вкладке браузера.
- Страница просмотра `/services/$buttonId` грузит кнопку через `GET /service/{button_id}`, показывает заголовок с хлебными крошками назад в `/services` и iframe с ссылкой; для ссылок, которые нельзя встроить, — предупреждение и кнопка «Открыть в новой вкладке».
- Иконки кнопок резолвятся через существующий хелпер `n` (`resolveServiceAssetUrl`) от baseUrl сервисного клиента; при отсутствии — плейсхолдер.
- Сгенерированный клиент `src/shared/api/services/` только потребляется, руками не правится.

## Capabilities

### New Capabilities

- `services-section`: каталог категорий с кнопками-сервисами, правила отображения по `view`, открытие по типу ссылки (`inapp`/`internal`/`external`) и просмотр внутренних форм в iframe.

### Modified Capabilities

None. Роутинг продолжает следовать существующему спеку `routing` (code-based дерево, hash-история) без изменения требований.

## Impact

- `src/app/Layout.tsx`: новый пункт навигации «Сервисы».
- `src/app/router.tsx`: маршруты `/services` и `/services/$buttonId`.
- Новый модуль страницы `src/pages/services/` по существующим конвенциям (`PageHeader`, `Container`, сгенерированные TanStack Query хуки).
- `src/shared/api/services/` — только чтение, сгенерированные файлы не изменяются.
- Зависимостей и сборка не меняются.
