# profile-achievements Spec

## Purpose

Обеспечивает работу с достижениями на странице профиля: просмотр собственных достижений пользователя и управление каталогом достижений (создание, редактирование, удаление, загрузка картинки, выдача и отзыв у пользователей) через achievement API (`https://api.test.profcomff.com/achievement`) с использованием общего токена авторизации приложения.

## Requirements

### Requirement: Достижения пользователя в профиле

Карточка «Достижения» в профиле SHALL показывать все достижения текущего пользователя из `GET /user/{user_id}`, включая достижения без картинки: название и описание каждого достижения доступны пользователю, а картинка (при наличии) загружается по абсолютному URL, разрешённому относительно базового URL achievement-клиента. Пока данные не получены, карточка SHALL показывать скелетон; при пустом списке — текст об отсутствии достижений.

#### Scenario: Достижение с картинкой

- **WHEN** у достижения пользователя заполнено поле `picture` относительным путём (например `static/1.png`)
- **THEN** приложение отображает изображение по абсолютному URL, составленному из базового URL achievement-клиента и этого пути

#### Scenario: Достижение без картинки

- **WHEN** у достижения пользователя поле `picture` пустое
- **THEN** достижение всё равно отображается в списке с названием и описанием

#### Scenario: Нет достижений

- **WHEN** у пользователя нет достижений
- **THEN** карточка показывает сообщение «Пока нет достижений»

### Requirement: Каталог достижений

Раздел управления достижениями в профиле SHALL показывать каталог всех достижений из `GET /achievement` с картинкой (разрешённой относительно базового URL achievement-клиента), названием, описанием и владельцем каждого достижения. Пока каталог загружается, раздел SHALL показывать состояние загрузки; при ошибке получения списка — сообщение об ошибке.

#### Scenario: Просмотр каталога

- **WHEN** авторизованный пользователь открывает профиль
- **THEN** приложение запрашивает список всех достижений и показывает их в разделе управления

### Requirement: Создание достижения

Раздел управления SHALL предоставлять авторизованному пользователю создание достижения (`POST /achievement`) с вводом названия и описания. При успешном создании новое достижение появляется в каталоге без перезагрузки страницы, а пользователь получает уведомление об успехе.

#### Scenario: Успешное создание

- **WHEN** пользователь заполняет название и описание и подтверждает создание
- **THEN** приложение отправляет запрос создания, обновляет каталог и показывает уведомление об успехе

#### Scenario: Создание с пустым названием

- **WHEN** пользователь пытается создать достижение без названия
- **THEN** приложение не отправляет запрос и указывает на обязательность названия

### Requirement: Редактирование достижения

Для каждого достижения в каталоге раздел управления SHALL предоставлять редактирование (`PATCH /achievement/{id}`) названия и описания с предзаполненными текущими значениями. При успешном редактировании каталог обновляется без перезагрузки страницы.

#### Scenario: Успешное редактирование

- **WHEN** пользователь изменяет название или описание достижения и подтверждает
- **THEN** приложение отправляет запрос редактирования, обновляет каталог и показывает уведомление об успехе

### Requirement: Удаление достижения

Для каждого достижения в каталоге раздел управления SHALL предоставлять удаление (`DELETE /achievement/{id}`) с подтверждением в диалоге. При успешном удалении достижение исчезает из каталога без перезагрузки страницы.

#### Scenario: Удаление с подтверждением

- **WHEN** пользователь запрашивает удаление достижения и подтверждает действие
- **THEN** приложение отправляет запрос удаления, обновляет каталог и показывает уведомление об успехе

#### Scenario: Отмена удаления

- **WHEN** пользователь открывает подтверждение удаления и отменяет его
- **THEN** запрос удаления не отправляется, достижение остаётся в каталоге

### Requirement: Загрузка картинки достижения

Для каждого достижения в каталоге раздел управления SHALL предоставлять загрузку картинки (`PATCH /achievement/{id}/picture`): выбор файла изображения (только непустые файлы с типом `image/*`) и отправку его как `picture_file`. При успешной загрузке обновлённая картинка отображается в каталоге без перезагрузки страницы.

#### Scenario: Успешная загрузка картинки

- **WHEN** пользователь выбирает файл изображения и подтверждает загрузку
- **THEN** приложение отправляет файл запросом загрузки картинки, обновляет каталог и показывает уведомление об успехе

#### Scenario: Неподходящий файл

- **WHEN** пользователь выбирает пустой файл или файл не-изображение
- **THEN** приложение не отправляет запрос и показывает сообщение об ошибке выбора файла

### Requirement: Выдача достижения пользователю

Раздел управления SHALL предоставлять выдачу достижения пользователю (`POST /achievement/{achievement_id}/reciever/{user_id}`) по числовому идентификатору пользователя. При успешной выдаче список получателей достижения обновляется без перезагрузки страницы.

#### Scenario: Успешная выдача

- **WHEN** пользователь указывает достижение и числовой идентификатор получателя и подтверждает выдачу
- **THEN** приложение отправляет запрос выдачи, обновляет данные получателей и показывает уведомление об успехе

#### Scenario: Некорректный идентификатор получателя

- **WHEN** пользователь указывает пустой или нечисловой идентификатор получателя
- **THEN** запрос выдачи не отправляется

### Requirement: Получатели достижения и отзыв

Раздел управления SHALL показывать получателей достижения из `GET /achievement/{achievement_id}/reciever` и позволять отозвать достижение у получателя (`DELETE /achievement/{achievement_id}/reciever/{user_id}`). При успешном отзыве получатель исчезает из списка без перезагрузки страницы.

#### Scenario: Просмотр получателей

- **WHEN** пользователь открывает список получателей достижения
- **THEN** приложение показывает идентификаторы всех получателей этого достижения

#### Scenario: Отзыв достижения

- **WHEN** пользователь отзывает достижение у получателя
- **THEN** приложение отправляет запрос отзыва, обновляет список получателей и показывает уведомление об успехе

### Requirement: Обработка ошибок и прав доступа

Все изменения, требующие прав (`achievements.achievement.create`, `.edit`, `.delete`, `.give`, `.revoke`), SHALL выполняться с токеном текущей сессии; при отказе сервера (нет прав, не авторизован и т.п.) приложение SHALL показывать уведомление об ошибке с текстом из ответа сервера (поля `ru`, `message` или `detail`), а не «молчаливый» сбой. Вход в приложение и набор запрашиваемых при входе скоупов меняться не SHALL.

#### Scenario: Недостаточно прав

- **WHEN** пользователь без прав `achievements.achievement.*` выполняет управляющее действие
- **THEN** приложение показывает уведомление об ошибке с текстом из ответа сервера и не изменяет состояние каталога

#### Scenario: Не авторизован

- **WHEN** управляющее действие выполняется без действительного токена
- **THEN** приложение показывает уведомление об ошибке авторизации
